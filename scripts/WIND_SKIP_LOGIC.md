# 万得同步脚本"跳过"逻辑说明

## 概述

万得同步脚本中的"跳过"统计，表示在处理配置列表中的某些标的时，由于特定原因没有进行数据加载。这**不是**跳过数据库表，而是跳过某些标的（tickers）的处理。

## "跳过"的三种情况

### 1. 无数据返回（最常见）

```python
if raw_data is None or raw_data.empty:
    logger.warning(f"[{ticker}] 无数据返回，跳过")
    total_stats['skipped'] += 1
    continue
```

**原因：**
- 万得API返回空数据
- 该标的在指定日期范围内无数据
- Wind API 未登录或权限不足

### 2. 没有新数据需要更新（最常见于日常同步）

```python
if load_data.empty:
    logger.info(f"[{ticker}] 没有新数据需要更新")
    total_stats['skipped'] += 1
    continue
```

**原因：**
- 该标的的数据已经是最新的
- 数据库中已有该日期范围的数据
- 增量同步时，没有检测到新增数据

**示例日志：**
```
[M0000185] 没有新数据需要更新
[M0041653] 没有新数据需要更新
[000300.SH] 没有新数据需要更新
```

### 3. 数据质量检查失败

```python
if not is_qualified:
    logger.error(f"[{ticker}] 数据质量检查失败，跳过")
    total_stats['failed'] += 1  # 注意：这里统计到'failed'而不是'skipped'
    continue
```

**原因：**
- 数据一致性检查失败
- 检测到异常波动
- 与数据库现有数据不一致

## 为什么显示"跳过22个"？

如果你运行脚本时显示"跳过: 22个"，可能的原因是：

### 场景1：首次全量同步后，日常增量同步

- 总配置：78个标的
- 已有数据无需更新：22个
- 实际有新数据：56个
- 结果：跳过 22个

### 场景2：部分标的无数据返回

- 总配置：78个标的
- Wind API返回空数据：22个
- 结果：跳过 22个

### 场景3：测试模式

```python
# 测试模式只处理指定标的
python scripts/sync_wind_data.py --test
```

## 如何查看具体跳过了哪些标的？

查看日志文件：

```bash
# 查找"跳过"或"没有新数据"的日志
grep -E "跳过|没有新数据" logs/sync_wind_2026-05-29.log
```

示例输出：
```
[M0000185] 没有新数据需要更新
[M0041653] 没有新数据需要更新
[000300.SH] 没有新数据需要更新
...
```

## 正常情况 vs 异常情况

### ✅ 正常情况

**日常增量同步（推荐每天运行）：**
```
成功: 56 个
失败: 0 个
跳过: 22 个  ← 表示这22个标的没有新数据，无需更新
```

这表示：
- 56个标的有新数据并成功同步
- 22个标的已经是最新数据，无需更新
- 系统工作正常

### ⚠️ 异常情况

**全量刷新时出现大量跳过：**
```
成功: 10 个
失败: 0 个
跳过: 68 个  ← 异常！首次同步不应该有这么多跳过
```

可能原因：
- Wind API未登录
- 网络连接问题
- 配置错误

## 建议

1. **日常运行**：使用增量同步（默认），跳过是正常行为
2. **首次同步**：使用 `--full-refresh` 参数强制全量刷新
3. **查看详情**：查看日志了解具体哪些标的被跳过

```bash
# 日常增量同步（可能有跳过）
python scripts/sync_wind_data.py

# 首次全量同步（不应有跳过）
python scripts/sync_wind_data.py --full-refresh
```
